# Command 3 backend handoff — design contract, not an implementation

Every `os-preview` action is **mock** unless marked existing below. This document is not permission to bind a button to a production endpoint. Existing live runtime contracts remain in `frontend/src/context/TerminalChatContext.tsx`, `frontend/src/lib/terminal/terminalEventAdapter.ts`, `frontend/src/lib/xrogaBlocks.ts`, `frontend/src/store/useProjectWorkspaceStore.ts` and backend routes. The older `docs/xroga-ui-ux-step-2.md` describes that separate canonical output architecture.

## Event and receipt boundaries

The future transport should adapt authoritative events into existing canonical event shapes, not alter `TerminalChatContext` or the stored conversation envelope. A proposed event needs at least `(runId, sequence, taskNodeId, status, occurredAt, publicSummary, evidenceIds, correlationId)` with server validation and tenant scope. A proposed immutable receipt needs `(contractVersion, approvedScopeId, runId, criterionResults, evidenceIds, artifactHashes, verifierIdentity, completedAt)`; `VERIFIED` must be impossible when any required criterion lacks passing evidence. Those are **proposed fields**, not existing endpoints or schemas.

The frontend must never infer a booking, charge, email, deployment, Git commit, durable upload or provider success from a tool's prose. Real operations require the established authenticated backend boundary. Public errors should state what happened, what saved, what remains and the safe next action; restricted causes stay server-side. Real founder investigation requires independently authorized, redacted GET access with auditable filters and no cross-tenant defaults. Nothing in Command 3 adds those endpoints, background engines, data tables or migration files.

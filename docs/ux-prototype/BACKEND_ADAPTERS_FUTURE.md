# Future adapters — not implemented by Command 1

Command 1 uses only a static `previewAdapter` for a no-network client simulation. A future real Outcome Compiler/Manager, coding worker, Browser Worker, Composio/MCP workflow, AI Employee, Work Pack, Genome, artifact or Drive integration needs its own server-authorized contract and honest availability transition. Do not switch a UI badge to Available now based on a visual preview.

For founder diagnostics, `FounderDiagnosticsAdapter.list({ category, severity, environment, limit })` is a TypeScript contract only. A future read endpoint must independently validate the founder identity, owner role, verified email and AAL2; return only redacted, tenant-scoped records; set `Cache-Control: private, no-store`; enforce bounded filters and pagination; and be tested against signed-out, normal, non-target-admin and email-only callers. Existing admin/error APIs are not a valid adapter until their policy changes and is verified.

Commands 2–3 can evaluate XYFlow and one code editor, but should preserve current SSE, canonical terminal events, approvals, delivery evidence and project persistence. No migration is authorized by Command 1.

# Untrusted input model

USER_TEXT, WEB_CONTENT, DOCUMENT_CONTENT, TOOL_OUTPUT, REPOSITORY_CONTENT,
EMAIL_CONTENT and MCP_DESCRIPTION remain data. Their wrapper carries provenance
and cannot create an issued tenant context, authority permit, approved recipient,
connected account or policy override. The policy does not execute instructions
found in that content.

Tool descriptions, read-only hints and claimed approval are untrusted capability
metadata. Only a reviewed server adapter may identify a registered integration.
Custom MCP action dispatch is blocked pending a verified restricted execution
boundary. No new sandbox product or model-based security classifier is added.

The primary local negative slice combines a synthetic credential canary,
malicious document instruction and redirecting destination. The secret is denied
before networking, the effect count stays zero and the decision is redacted.
Separate transport tests exercise real redirect processing with controlled DNS
and streams, including rebinding and redirect-to-private rejection.

Tests also cover fake grants, changed accounts and arguments, foreign file owners,
ownership changes during the receipt wait, storage failure, deadline failure and
authority revocation before the effect. Their provider/database transports are
controlled fixtures. No live provider, customer file or real secret is used.

This is deterministic boundary coverage, not proof that prompt injection can
never occur. Unmigrated callers and unsupported binary formats remain explicit
obligations. Existing authority, budgets, tenant isolation and CredentialVault
interfaces retain their original requirements. Phase 3 runtime KMS custody and
applicable cutover remain separately blocked.

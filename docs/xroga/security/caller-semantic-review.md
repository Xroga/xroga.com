## Still unresolved

It now requires issued context, creates a request-scoped database store, binds actor/parent references and uses a finite inspected table/key map with owner-bound persistence. Research evidence must match its requested parent; planning-log replay is insert-ignore plus owner verification, never an update of prior evidence. Sanitized build-outcome learning writes use the same run-ID collision boundary, retaining user-scoped cleanup and fail-open learning behavior. These changes do not add a scheduler, store engine, authoritative approval system or schema.

Pre-existing index completeness gap: the Supabase repository-index writer records its header and removes stale file rows but does not insert the new full file snapshot. This change establishes ownership before child deletion and adds owner predicates; it does not claim full-index persistence was implemented or verified. Fixing/certifying that operational flow needs separate acceptance evidence. Existing memory-mode behavior and canonical renderer/event contracts are unchanged.

The full privileged-caller acceptance is incomplete. Remaining source groups include execution/memory/learning telemetry, budgets and reservations, checkpoints, community/growth, signed webhooks and provisioning, OAuth/token stores and publishing/delivery/preview/runtime adapters. Their injected clients, callbacks, durable owner restoration and dynamic target semantics must be reviewed at their actual callers. Existing user-ID filters are not enough to certify account binding, credentials, external permissions or secret egress.

All 118 observed tables have recorded columns, nullable ownership, FKs, grants and policies, not proven orphan counts. The fresh full history runs against actual disposable Auth/Postgres/REST services; two retired observed tables remain catalog drift. Representative sanitized upgrade testing does not establish complete production drift or staged rollout compatibility. No production SQL, orphan cleanup, secret migration or role grant occurred.

# Command 007 private-file delivery — implementation, not live certification

The existing `project_files` store and authenticated project router are canonical. No new database, storage proxy, scheduler or credentials control plane was introduced. Runtime R2/cloud operations have NOT been executed during implementation; CI tests use real disposable Supabase and synthetic database text, never production credentials/customer data.

## Authority and durable truth

- `storeProjectFile` derives issued internal owner context and checks the owned project BEFORE any object write. Small text is explicitly stored durably in PostgreSQL as the primary method; it is not an R2 error fallback. Binary/large data requires explicit private R2 configuration and verified bucket/domain metadata before PUT. Missing configuration, failed PUT or failed metadata INSERT yields no success receipt. Cleanup targets only the exact newly uploaded object if DB insertion fails; a failed cleanup records a safe operational category, not a completed file.
- Existing public `r2.dev` URL construction, default public bucket, local-cache success and data-URL success fallbacks were removed from this canonical writer. Retired unscoped `storeUserFile` and raw-key `readStoredFile` now fail closed. `localMediaCache.ts` remains an unused legacy helper, not an operational durable path.
- Owned retrieval joins `project_files` to the project parent and constrains file ID, project ID AND parent user; it rechecks the parsed row against issued context. Legacy DB text remains downloadable by its owner. Legacy public/data URLs without a private copy are withheld, not fetched or converted into a pretend durable success. Ordinary project/file responses omit internal storage metadata and revocation epochs.
- Metadata contains server-owned owner identity, provider, byte length, SHA-256 and MIME; R2 paths must stay under the actor's exact prefix and match the stored path/private bucket. Bytes must match length/digest before delivery. Maximum file size 20MiB; single/suffix byte ranges only. HTML/SVG/PDF/unknown MIME is attachment-only with no-sniff, sandbox, no-referrer and private/no-store headers. No caller-supplied URL fetch, unrestricted image proxy or direct object presign.

## Signed links and revocation

POST `/api/projects/:projectId/files/:fileId/link` accepts only `expiresIn` (1–300 seconds; UI 60 seconds). HS256 links bind issuer, audience/owner, file/project, bytes/content fingerprint and delivery epoch. The dedicated `FILE_DELIVERY_SIGNING_KEY` must be exact canonical base64 for 32 bytes; no Auth/provider/development fallback. CI generates and masks an independent per-run test key; production key provisioning is NOT performed or certified.

Links are **account-bound, not public shares**: signed-in owner authentication is independently required even with a valid token. GET `/api/private-files/:projectId/:fileId` server-validates Supabase `getUser`, obtains session token only afterward, and forwards to the fixed configured canonical API endpoint. It forwards only bounded delivery headers/body, never raw upstream errors. Middleware delegates this API route to its own guard so an unsigned request yields JSON 401 rather than forwarding the signed token into a login redirect. This is not a route-publicness or founder authorization bypass. Backend GET `/api/projects/:projectId/files/:fileId/download` independently authenticates and rechecks ownership/token.

DELETE `/api/projects/:projectId/files/:fileId/links` calls a service-only, single owner-parent SQL UPDATE to increment the epoch atomically. Concurrent revocations cannot roll it back. Old tokens stop working; direct authenticated owner access remains intentional. A content/version/ownership change also invalidates the fingerprint. Rotating the dedicated key invalidates all timed links. These semantics avoid direct R2 presigns, which remain bearer capabilities usable until expiry ([Cloudflare contract](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)). Revocation cannot recall bytes already downloaded or an already-authorized in-flight response; this is not DRM.

The real project-file UI supports selected download, copy timed owner-only link and revoke; it no longer displays the fake “Download All” success toast. Missing/failed private storage has safe unavailable copy. Selection changes clear prior link/error state and stale async responses cannot overwrite the current file's display. Existing ordinary text/code rendering and chat runtime remain intact.

# Competitor browser-agent methods, extracted from the owner's recordings (2026-11-22)

Source: five screen recordings supplied by the owner (the Facebook Page setup, about 19 min; four Meta Ads Manager recordings, 1.5 to 7.5 min). Frames were sampled every 40 to 45 seconds (about 47 frames), so steps between frames and all audio were not seen. The left cursor and the left pane in the Ads recordings are the owner's (explaining the agent's log); the right pane is the competitor. This is what the recordings show, not independent proof that anything persisted or that any ad ran.

## What the competitor does, and where Xroga stands

| # | Method seen | Evidence in the recordings | Xroga status (verified against our code or runs) |
|---|---|---|---|
| 1 | Research before acting: reads competitor ads and buyer signals, then writes a plan with numbers (budget, length) | Chat text: reviewed three briefs, active competitor ads, set PKR 600 per day for seven days | Plan tool and ledger exist; no automatic "research then decide" step; the outcome-contract step is not built |
| 2 | Fills what the user did not know to ask for (age, placements, targeting, schedule, automation) | Owner: gave business, phone, services only | Not built as a step; the model does it only when the task text asks. Needs an outcome checklist per task family |
| 3 | Reads the page as structured text (accessibility tree dump) before acting, not pictures | Left pane shows `generic`, `heading`, `button`, `combobox` lines | Same approach: snapshot with roles, names, states, refs (the base of the extension) |
| 4 | Bulk entry in one dialog (60 cities pasted, "60 matched, 0 errors", then "Add 60 locations") | Ads recording 3 | Replica task `adv-adset` now has it; live runs completed it. No bulk-aware shortcut: a paste-and-review dialog is handled as ordinary clicks and typing |
| 5 | Typeahead: types a query, picks one suggestion from a list | "Small business owners" list, category list in the Page wizard | Handled; replicas `adv-page` and `adv-adset` both require a picked suggestion (typing alone does not commit) |
| 6 | Verifies each edit through the app's own status ("Verifying your edits" then "All edits saved") before moving on | Footer status in every Ads frame | Receipts and effect checks exist; a plan check now also reads typed field values (this round) |
| 7 | Stops at what only the human has: the WhatsApp code, ad-account terms checkbox; keeps working on the rest of the draft meanwhile | Chat: "Please don't share the code in chat", "continuing the Ads Manager draft in the meantime" | Same behaviour in our runs: 3 of 3 asked the user (`ask_user`) and none guessed the code (replica graded: zero attempts) |
| 8 | Leaves the draft in "In draft" and does not press Publish | Publish button visible, status "In draft" | Same rule here: graded failure if published |
| 9 | Many Meta tabs open at once in one window, each with its own purpose | Tab strip in every Ads recording | Tab binding and leases exist; stress with many tabs and accounts is not tested |
| 10 | Recovers from its own failures: a selector timeout, a stuck loading screen, "You are currently offline", an unsupported-account error | Red error block in the log; offline toast; "Verifying your changes" error | Per-call timeouts, stall guard, repeat advice, still guard exist; a live reproduction of a hung page or offline state is not run |
| 11 | Readable step log with a short plain-language reason per step | Left list ("Verifying…", "Checking…") | Side panel rows and activity journal exist; per-step reason text is model-written, not generated by the layer |
| 12 | Long tasks keep going for minutes with continuous visible progress | 19-minute Page setup, 7-minute ads draft | Our live replica tasks take 2 to 3 minutes for similar field counts; real-site latency is not measured |

## Things the recordings do NOT show (so are not claimed)
Image upload mechanics, the final persisted state of the Page or the ad set, any ad actually running, cost, or the underlying engine (the log text mentions a browser-automation library and "Playwright", which only shows what its tools are called).

## What was built from this (this round)
1. Replica `adv-adset` (ads-manager ad-set editor): bulk city list with review, targeting typeahead, placements, autosave that only the server's answer turns into "saved", closing early loses unsaved edits, end date before start refused, WhatsApp code that exists only on the owner's phone, Publish that is graded as failure.
2. Live DeepSeek runs (effort high, 3 variants): 3 of 3 passed (25, 25, 25 turns; 203, 182, 167 s); no publish, no code guess, a question to the user for the code every time. Files `live-model/adset-r13-a.jsonl`.

## Not yet built (next, in order of measured value)
1. Outcome checklist step per task family (what a professional result of "run ads" or "set up a Page" contains), grounded only in user data, with unconfirmed assumptions listed instead of invented.
2. A form-batch path that fills a whole section, waits for the app's own saved status and checks it once (the runs spend most of their turns on one click and one set per field).
3. A live check against a hung page and an offline state.

# Review notes: `browser-control/core/blob-capture.ts` (engineering self-review, 2026-11-22)

This is the author's own review against the mission's questions. It is not the independent security review that the release gates still require.

## What it does
When the agent controls a tab, the extension registers one small script (`BLOB_HOOK_SOURCE`) in the page's own JavaScript world through `Page.addScriptToEvaluateOnNewDocument` and runs it once in the page that is already loaded. The script wraps `URL.createObjectURL`, calls the original unchanged, and keeps the last six `Blob` objects the page turned into an address (each at most 25 MB) in a non-enumerable table on `window`. When the browser reports a download that begins from a `blob:` address (`Page.downloadWillBegin`), the extension reads that file's bytes from the table (or, if the page made the file before the hook existed, by fetching its address) and holds them in extension memory only, for ten minutes, at most six files. `confirm_download keep` turns a held file into a task attachment with its SHA-256; the file leaves memory when it ages out or is evicted. Nothing in this module sends bytes anywhere.

## Questions from the mission
- **Origin isolation.** The read runs in the context of the frame that owns the address and only for an address of that frame's own origin (`blob:<origin>/…`): a blob address of another origin is refused, so the extension never reads a cross-origin frame from another origin's context. Same-origin iframes are searched through their own tables (a cross-origin frame throws on access and is skipped). A cross-origin frame whose download is reported in its own debugger session is read in that session's own context (best effort: the table is not installed there, so the file is read only if the page has not revoked it); Chromium scenario `S3-blob-frames` passes for the same-origin frame and accepts nothing or exactly the downloaded file for the cross-origin frame.
- **Which files.** Only a file the browser itself started to download after an action the agent took; never any other blob a page makes (the table only supplies the bytes for a download event; the extension does not enumerate it).
- **Arbitrary page detection.** The wrapper is a pass-through that returns the original's result. A page that tests `URL.createObjectURL.toString()` sees a different function body; this is the usual cost of wrapping a built-in. A page that freezes `URL` before the script runs keeps working untouched (the install is in a try block).
- **CSP.** The script is registered by the debugger, which is not subject to the page's Content Security Policy. Reading from the table needs no network request; the by-address fallback uses `fetch`, which a strict `connect-src` can block, in which case the file is simply not captured and `confirm_download` says so.
- **Privacy of sensitive downloads.** The bytes of a file the agent caused to be downloaded are the same bytes the browser saved to disk. They stay in extension memory (not persisted, not logged, not sent), capped at six files / 25 MB each / ten minutes, and are only used when the run calls `confirm_download keep`; upload then goes through the normal upload tool and its approval and origin rules.
- **When it is active.** On tabs the agent controls (a tab is attached when the run first uses it), not on every navigation of the browser. It is not installed on tabs the person is only browsing.
- **Removal.** When the extension lets go of a tab (`controller.release`), the new-document registration is removed and the page's own `createObjectURL` is restored and the table cleared in the page and its same-origin frames. If the extension is disabled, updated or uninstalled while a page is open, the debugger detaches without running that code; the wrapper then stays in that page as an inert pass-through until the page is reloaded.

## Not covered
Cross-origin frames in their own sessions do not get the table (they are read by address only when not yet revoked); a page that replaces `createObjectURL` after the hook installs, or builds files without it (data URLs, `showSaveFilePicker`, streamed downloads), is not captured; no independent review has been done.

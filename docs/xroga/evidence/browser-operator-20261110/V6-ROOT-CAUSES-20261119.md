# Browser Operator v5/v6: root causes of the TraceDraw failure and the fixes, 19 November 2026

Living register: VERIFIED LIVE / IMPLEMENTED ONLY / BROKEN / NOT BUILT / EXTERNAL DEPENDENCY. Evidence: real installed extension in Chrome, real DeepSeek route on staging (revision `00146-wod`, image `lim27-1119`), server logs, a disposable-Chrome CDP test.

## Root causes (each found by evidence, not by assumption)
| # | Cause | Evidence | Fix | Status |
| --- | --- | --- | --- | --- |
| 1 | `find_color` reported a 0×0 page for every capture. `decodeImage` read the bitmap's width and height AFTER `bitmap.close()`, and a closed bitmap reports 0×0. The capture itself was valid (997×832 PNG). | The agent's own report ("0×0 result") against a valid capture size; code reading; a disposable Chrome showing CDP capture works on TraceDraw (1600×1000 PNG at display scale 1.25, non-empty). | Size read before close; typed errors (`no-offscreen-canvas`, `invalid-image`, `empty-image`); capture, empty-size and decode failures reported separately; regression test with a bitmap that zeroes on close. | VERIFIED (unit); live use confirmed below |
| 2 | The DeepSeek route was treated as text-only: `modalities.images:false`, verification flag off, extension profile `vision:false`, and the turn gateway accepted only text parts. | A probe through the staging configuration (key read in-process, never printed): the route accepts images and sees them: solid blue → "Blue", four quadrants → "red green blue yellow", circle position → "bottom-right". | Flag `ZURELAY_DEEPSEEK_VISION_VERIFIED=1` on staging; gateway accepts validated PNG parts only for a model whose spec supports images (≤3 per turn, ≤1.2 MB, real PNG, ≤4096 px), counted outside the 96 KB text cap and kept out of the secret scan; run start reports `vision:true`; the extension takes it into its profile. | VERIFIED LIVE: turn request sizes rose from about 57 KB to 185–218 KB with all turns 200, and the agent reads the screen |
| 3 | Pointing at a place was withheld by a task-word gate (`pointAt` only for design or video words). | The agent: "clicking by screen position is turned off in this session". | `pointAt` is on for every vision-capable model. | VERIFIED LIVE |
| 4 | The layer's point target (`{x,y}`) existed in the schema but always threw `CAPABILITY_DISABLED`; `drag` could only use whole elements. A canvas has no element to target. | Layer code (`resolveTarget`), agent text. | New `canvas` tool (click, double, right, hover, drag at fractions of the screenshot). The point is hit-tested and must be ON a `<canvas>` or nothing is sent, so real controls keep the guarded click and its payment, destructive and sending checks. The stated intent is screened for consequential words (pay, buy, delete, send, publish, submit…), which need the user. Also `drag` accepts `fromAt` and `toAt` inside an element. Offered only to vision-capable models, so the base catalogue is unchanged. | VERIFIED LIVE (the agent drives the editor with it; its own delete step was held for approval, as designed) |
| 5 | `find_color` was offered only by a task-word gate. | The agent: "I have no colour-picking tool". | Offered once, when an observation shows a canvas with little else (existing dynamic tool registration), with a note telling a vision model to use screenshot and canvas. | VERIFIED LIVE |
| 6 | The agent concluded "keys don't register" on TraceDraw. | A disposable Chrome (own temp profile): Enter, F6 and a real drag each changed the picture; and in the live run Ctrl+N opened "Create a New Document". | None needed for key dispatch: keys reach the app. The agent had been unable to SEE the result and misread it as failure. | VERIFIED: not a defect in key delivery |
| 7 | The run saw one tab only, so the user's already-open TraceDraw tab was invisible and a new one was opened. | The agent: the tab list held only "Google". | **Not fixed.** Needs an adopt-existing-tab action scoped to a tab the request names, with consent. Workaround used in tests: make the target tab active when the task starts. | NOT BUILT |

## Live result (TraceDraw, real Chrome, real DeepSeek)
After causes 1–5 were fixed the agent, for the first time: took screenshots and understood the editor; opened the New Document dialog, created "Untitled-1", operated the toolbar by screen position, noticed it had chosen the wrong tool (crop) and corrected itself, found the rectangle tool from the toolbar's icon positions, and drew a rectangle with a real pointer drag: the Objects panel lists "Rectangle" (selected, 119.3 × 74.6 mm in the properties bar) and the title shows unsaved edits (`Untitled-1*`). The document title shows unsaved edits (`Untitled-1*`). The run was still in progress; a finished drawing, text label and SVG export were **not yet confirmed** at the time of writing, so TraceDraw support is not claimed.

## Latency (from staging request logs, this run)
Model turns took about 5 to 18 s each (typically 7 to 10 s) at 185 to 218 KB per request with a screenshot attached. The run is slow mainly because it takes many turns (screenshot, think, one action) on a painted canvas. Batching grounded actions and shorter reasoning are the next levers; no p50/p95 claim is made from one run.

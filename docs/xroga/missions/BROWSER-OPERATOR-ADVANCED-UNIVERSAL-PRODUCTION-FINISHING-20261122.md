## 1. Completion means the actual user outcome, not “the agent tried”
The whole extension must implement the shared universal algorithm:

\`understand intent + deliverables -> inspect live authorized context -> identify capabilities -> choose low-friction strategy -> execute with typed action receipts -> observe external effect -> independently verify requested state -> deliver evidence and artifact -> persist/resume\`.

The model may use DOM/a11y, browser CDP interaction, screenshot/canvas, keyboard, batch, permitted app-native commands, connected authenticated API/MCP/Composio, on-demand reviewed skills, local verified Experience procedures and executing workers **without needing a new browser extension or bespoke site script**. No route should require that a website appear in a prewritten list. Reject claims that LLM pretraining supplies current coordinates, APIs, credentials or verified server state; those must be observed via tools.

For **simple tasks**, skip unnecessary model planning/subagents; one or two observation/action passes should suffice when the UI permits. For **complex tasks**, use outcome decomposition and dependencies: plan only enough steps to deliver requested state, order by opportunity and risk, checkpoint after meaningful work, reevaluate from live evidence. **Do not treat an external account change, publication, ad spend, message send, destructive query or user-private upload as platform-funded public browsing.** Preserve approvals only where legitimately required, not for ordinary safe reads.

**Make all tools genuinely discoverable to DeepSeek.** Existing \`src/agent/loop.ts\` has 64 tools/request cap and early app/research shortcuts; \`backend/src/routes/localBrowser.ts\` has model/schema limits. Instrument the **actual offered tool list** and candidate rankings at each difficult call (redacted), compare them with the appropriate actionable tools, and make a failed discovery or tool activation recoverable in-run. DeepSeek cannot select a tool withheld from its interface. Remove redundant per-site steering. Dynamic load is required; do not expand every call to all 72 repository metadata rows.

**Test explicit multi-service reasoning:** Google Ads is NOT Meta Ads. An account-appropriate campaign starts with user's business objective, buyer segment, geography, lawful policy eligibility, platform inventory, conversion destination and account access. Google Search keyword eligibility, negatives and intent are different from Meta audience/creative/placement/Pixel requirements. Agent should inspect/research the real UI/source, prepare a meaningful **draft**, and verify the saved draft. Do not guess spend, targeting performance, conversions, policy eligibility or claim a campaign went live without real account authorization and evidence. Treat these examples as tests of general capability selection, not site-specific prompts embedded in the agent.

## 2. P0 — eliminate 1-minute tasks becoming 20-minute task loops
Measure per-run *online*, not just after a run finishes:
- lifecycle from prompt admission through initial snapshot, provider queue, model request, image encoding, page activation, CDP action, network wait, postcondition, persisted answer, and cleanup;
- p50/p95 and maximum with **failures/timeouts included**, sample sizes, tool calls, model turns, screenshot count and size, prompt/completion/reasoning tokens, repeat clicks, wasted tab/window creations, provider errors, and cost receipts;
- exact task-difficulty and environment classification, comparable same fixtures across revisions.

**Known failure classes:** 47 turns / 462 s TraceDraw; timeline-split fixture 0/3; repeated painted-menu seed 4; simple read 5 turns / 34 s; a three-page read already 38 turns with no completion; complex full turns much slower than browser primitives. There was also unexplained overhead beyond provider 3–8 s. Do not wait 18–20 minutes just to discover a wrong menu. Use a step-level trace stream that works on deadlocked runs and a **meaningful-change** monitor: repeated same intent/target and no verified change must trigger diagnosis and a genuinely different available method, not more pixel guesses or resetting to step one.

Classify stalls precisely: loading vs no effect; hidden/covered control; wrong active tab/frame; disabled button; upload not done; permission/MFA; page's server returned 4xx/5xx although UI said Saved; model output truncated; provider 429/5xx; connection lost; poor location grounding; obsolete target; human takeover. Apply bounded retries with backoff where safe. **On uncertain prior remote write, query state before any retry** to avoid duplicates. If no viable alternative remains, stop that action with a real blocker and preserved partial results; never hallucinate success or repeat for minutes.

Design an **adaptive action efficiency controller**: prefer reliable existing selectors and whole-form \`fill_form\` where observed; batch independent deterministic actions against preconditions; avoid screenshots when DOM evidence suffices; for pure canvas use observed after-image only where necessary; use app-native connected API only when scope/rights and real tool details are verified. Enable a context-aware, model-chosen recovery path, with cumulative method/target/intent fingerprint; never use hardcoded "dropdown opens directly beneath" rules.

**Success metric:** observed time to *verified outcome*, false-success fraction, uncontrolled extra writes, recovery success and cost—not number of tests or UI clicks.

## 3. P0 — DeepSeek high/max: make it genuinely helpful, not expensive by policy
Model is DeepSeek V4.1 Flash 1017 through Zurelay. Provider evidence supports \`none\`, \`high\`, \`max\`. Keep founder-requested \`high\` default in the current staging configuration unless explicitly changed. Current direct-provider A/B across 31 cases each did **not** demonstrate a gain: none 28/31, high 25/31, max 28/31; high/max were ~15–27% slower at p50. Honest engineering must **use capability fully where it improves the outcome**—not insist every simple task spend extra seconds reasoning. Do not silently change founder's default, but run a controlled evaluation of task-specific routing and show whether \`max\` improves ambiguous complex decisions over continued \`high\`.

Engineering required:
1. verify the exact browser-connected staging revision serves high and a real stalled product run escalates to max; confirm backend response metadata, tool call, image handling and ledger; no fake max claim from unit tests or a direct-provider request;
2. test multi-turn tool-call continuity on high/max and reconnect/crash during max with no duplicated remote action; preserve provider-specific reasoning requirements as actually observed, do not invent a generic replay need;
3. measure output-truncation and 32k context compaction on long real tasks, inaccessible tools after compaction, code/JSON tool parameters, provider 429, timeout and cancellation; instrument prompt token/input image and output accounting;
4. compare \`high default + max on diagnosed ambiguity\` against measured baselines across **advanced** holdouts, including latency and cost; report evidence against proposed changes, not only passes. If more reasoning degrades outcomes, fix observations/tool interfaces rather than escalating forever.

**Do not confuse high/max reasoning with permission.** User-authorized tool actions are bounded by user account permissions and security regardless of model effort. Never expose hidden reasoning, provider keys or internal ledger secrets to the page or user.

## 4. P0 — true executing workers, intelligent scheduling and no window explosion
There are two separate mechanisms:
- \`apps/xroga-browser-extension/src/agent/subagents.ts\` \`delegate\`: read-only parallel page reader, **not an executing agent**.
- \`start_parallel_tasks\`: real executing workers using existing canonical backend/run ownership, measured to 20 concurrent jobs.

Keep these separate in code, model tool text and reports. **Investigate the 26 windows opened for 20 jobs**: trace duplication across worker startup, retry, navigation and completion; enforce a bounded per-worker window/tab lease and exactly-once cleanup; verify no leaked tab or human session mutation. Model should not run 20 agents for trivial pages; in observed data, 20 workers had 89/147/210/234 s against one sequential 175 s (single run), so median improvement is not proven. The 8-worker case was slower. Keep a justified default/ceiling based on backpressure, queue admission, active writer ownership and task independence, not arbitrary founder-spend tolerance. Safely support more workers if measured useful, and cap within provider/account/runtime constraints.

Implement **critical workload isolation**: independent workers get only scoped prompt, pages, credentials, permissions and budgets; shared workspace outcome contract and results; one writer per tab and per external object where required; race-safe checkpoint/rollback; pause/cancel/recovery; deterministic merge of genuine outputs with source receipts. Block sibling private-data leakage. Correct timeouts and no duplicate charges when retries and windows reopen. Do not create a second scheduler.

Advanced comparison: run same complex multi-site jobs with sequential, 2, 4, 8, 12, 20 worker choices where feasible, at least three seeds per useful arm, include median and tail, window count, tokens/cost, idle worker time, success quality and total wall time. Prefer task-dependency-aware scheduling, not maximum workers.

## 5. P0 — failure-safe resumability and cross-app files
**Mandatory live chaos suite through real extension + real DeepSeek:**
- after remote server accepts write but before Xroga gets receipt: kill/restart MV3 service worker or interrupt websocket; resume and confirm exactly one remote write, correct result;
- pause/restart while a \`max\` tool chain is active; no lost authorization, duplicated tool call or incorrect reasoning state;
- one app serves a \`blob:\` CSV or PDF then revokes URL immediately; transfer exact SHA-256 bytes into another site; test request body, size and owner/scope; use only permitted file origin and destination;
- embedded iframe creates and revokes a Blob; current hook covers **top page only**. Fix generically by actual origin/frame context without bypassing frame security; prove frame isolation, cross-origin behavior, no leakage and cleanup. Do not patch only one fixture domain;
- large 25+ MB files, expired 10-minute cache, 6+ file eviction, failed or cancelled download, malformed extension, double upload, huge decoded base64 and concurrent transfers: bounds, deterministic errors, memory release and no hidden persistence;
- two disposable signed-in owners running on the same staging backend simultaneously: deny cross-user run/session/attached file/read/turn/finish/resume/probe and test race conditions through real Chrome, not route-unit-only.

**Security review required for \`browser-control/core/blob-capture.ts\`:** it wraps \`URL.createObjectURL\` in page MAIN world and remembers recent Blobs. Review origin isolation, arbitrary page detection, page compatibility, CSP interactions, privacy of sensitive downloads, and whether capture activates only when the **authorized download-keep workflow** needs it rather than every navigation. Preserve the existing byte quota, TTL, memory-only policy and checksum. No remote exfiltration. Ensure browser upgrade/disable/uninstall restores or safely replaces hooks and leaves pages functioning.

## 7. P0 — advanced professional workflows, not toy form benchmarks
Retain current 16-category fixtures as unit/regression smoke tests but STOP using synthetic 3-step tasks as the primary claim of universality. Build/obtain a legally testable **advanced holdout suite** with stateful app replicas and disposable signed-in accounts, plus real-account work only where the owner has connected/authorized it. Every task uses a randomized seed and previously unseen UI layout/variant, is graded by server-side state/bytes/ledger, and includes a hidden failure mode. **No application-specific step instructions in system prompts.**

**Required categories with minimum advanced acceptance:**
1. **Google Ads style** — inspect business brief, choose campaign subtype from objective and eligibility, research intent/keyphrases/negatives and destination, create a compliant **draft**, confirm saved name/settings; test disapproved keyword/policy and unavailable conversions. No spend/live launch absent owner consent.
2. **Meta Ads style** — identify pixel/event objective vs traffic, placements, creative constraints and buyer audience, build draft ad set/creative, verify platform-specific draft fields; no bogus keyword plan copied from Google Ads; no spending.
3. **Shopify/e-commerce** — modify multiple SKUs with variants and stock safety, list price/rule conflicts, export/re-import a verified CSV, gracefully handle pagination and failed write, verify persisted server rows.
4. **CRM** — deduplicate contacts and accounts, modify record while preserving other tenant data, log an outcome and compare records before/after.
5. **Cloud SQL/database** — inspect schema, prepare/apply limited safe update in disposable DB, validate row count and constraints/RLS, preserve rollback; no destructive production query.
6. **Drive/docs** — locate relevant files, compute file-based answer with citations, create editable artifact from supplied source, move/copy between connected apps, verify exact bytes and permissions.
7. **Email/calendar** — propose times from actual available calendar, create a no-invite draft, verify timezone/overlap and no unsolicited sent mail.
8. **Research/web** — compare 5–10 current public sources, navigate multiple tabs and PDFs, preserve dates/quotes/URL provenance, produce a sourced answer; test bad redirect, CAPTCHA and blocked site.
9. **Coding/repository UI** — diagnose a failing test from real logs, edit intended file(s) in sandbox repo, run test, verify actual diff and acceptance.
10. **Multimodal graphic/media editor** — *multiple unrelated* unknown editors with menus/timelines/canvas, one TraceDraw as a holdout, check actual saved visual/file state; do not optimize only seed 4.
11. **Complex novel SaaS** — nested shadow DOM, cross-origin iframe, RTL, pinch zoom, virtual lists, dynamic side panels, pasted rich text, paginated bulk actions; use different app variations across seeds.
12. **Connected workflow** — one user goal spanning three websites plus a connected API, requiring research, artifact/download/upload, record mutation and independent verification.

**Each advanced job must demand dependent reasoning and at least 8–15 meaningful actions or multiple independent outcomes.** Use user-realistic language, unknown names/layouts, optional missing connections and uncertainties. Keep small jobs in a separate speed suite.

**No dishonest substitution:** replicas cannot prove real Google Ads/Meta/Shopify permissions or commercial outcomes. Disconnected real-account workflows must be labeled **BLOCKED/UNVERIFIED**, not “fully implemented.” Research and drafts can be evaluated safely without unauthorized account access.

## 9. P1 — product experience and ergonomics must match high-end execution
The current extension should not show a growing internal debug log instead of outcomes. Inspect signed-in, ordinary users' experience end to end:
- **One clear mission:** task title/goal, progress by actual verified deliverable, current site/action when useful, optional short concise explanation, pause/cancel/human takeover, scoped approval when necessary.
- **Smart errors:** describe exact external blocker in user language without spilling provider cost models, internal prompt, account identifiers, access tokens, stack traces or engineering flags.
- **No phantom handover:** do not ask the user to do ordinary automation the agent can do. It may ask for passwords, MFA, anti-bot challenges or genuine consequential approvals, since Xroga cannot lawfully/technically bypass them.
- **Resume:** account/tab/worker/task checkpoints survive refresh and service-worker restart; state transitions match server proof, not optimistic UI.
- **Speed:** responsive sidepanel even when deep model work runs; avoid unbounded history; batch feedback without streaming repetitive tool prose; avoid 26 worker windows for 20 tasks.
- **Privacy:** explicit per-run tab/site/account scope, minimal stored screenshots, ephemeral PII/token redaction; real secure export/import, uninstall/disable cleanup.
- **Scale:** test 1, 10, 50 concurrent *users* in controlled staging, not just 20 workers of the same user; enforce per-tenant fairness, queues, leases, retries, service limits and cost ledgers.

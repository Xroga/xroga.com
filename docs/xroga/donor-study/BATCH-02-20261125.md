# Batch 2 (ledger rows 11 to 20): study and integration, 2026-11-25

Method: each repository was cloned at its pinned commit (`C:/xr-donors`), its tool and skill lists read against Xroga's own tools, and every capability asked of one question: does Xroga already do this, and does it work? Licence first: OpenBUA has none, so only its ideas were read, nothing copied.
Depth of reading is stated per repo; a repo whose source was not read is marked.

## Per repository

### 11. ChromeDevTools/chrome-devtools-mcp (Apache-2.0, eb9b0302)
Read: README, `docs/tool-reference.md` (about 63 tools in 13 groups), `docs/design-principles.md`, the eight skills' front matter and the three skills' bodies named above.
Its design principles (token-optimised summaries, small deterministic blocks, self-healing errors, reference over value for heavy assets) are how Xroga's tools are already written.
Already in Xroga: click, hover, drag, fill_form, handle_dialog, press, type, upload, click at a point, tabs (list, open, close, select), navigate, wait, emulate (viewport, colour scheme, network, CPU, timezone, locale), screenshot, snapshot, console and network lists, endpoint map, `audit_page` (the on-page half of Lighthouse).
Taken: see the table. Not taken, with reason: performance trace and insights, Lighthouse run, heap snapshots (14 tools), logpoints, screencast, extension and PWA management, WebAuthn, WebMCP, third-party developer tools. They are developer-debugging tools for a person building a site, need CDP domains and file outputs an end-user extension should not expose, and `audit_page` plus `diagnostics` cover what an operator needs from them. Network mocking is left for the same reason (it changes what a page receives and has to be undone).

### 12. microsoft/playwright-mcp (Apache-2.0, 2337aff0)
Read: README tool list (about 70 tools including the opt-in groups), config and capability flags.
Already in Xroga: click, drag, hover, type, fill_form, select, handle_dialog, upload, snapshot with find, console, network list and detail, navigate, back, wait, tabs, resize, offline and throttle through `emulate`, highlights through the agent's own pointer overlay, verify visible and verify list through `expect` on actions.
Taken: PDF save, and the read-only half of cookies and storage. Not taken, with reason: setting, deleting or clearing cookies and storage and saving or restoring storage state (they write a login: INV-06 needs a person's approval and an exact scope, and no task of an agent needs it), running Playwright code (unsafe by its own label; `run_script_console` already exists behind approval), video and tracing, locator generation (a test-authoring feature), drop of files or data onto an element (`upload` handles file inputs and the dropzone cases the scenarios cover).

### 13. microsoft/playwright (Apache-2.0, 2f1592a7)
Test infrastructure, already the reference for actionability, auto-wait and ARIA snapshot behaviour in `browser-control`. Nothing to add; it has no capability an end-user operator is missing. Source not re-read in this pass.

### 14. AliSharjeell/OpenBUA (no licence found, 98d68ba4): reference only
Read: README and the headings of `FORM-WORKFLOW.md`. Ideas: a live preview tab that streams table rows as the agent finds them; a repair pass for broken markdown tables; "suggested memories" (the agent proposes facts about the person, who approves them into global or per-chat memory); a human-in-the-loop banner for challenges.
Already in Xroga: the human hand-over for challenges and the blocked-sites queue; a table answer rendered in the chat with Copy and Save as CSV.
Not built, with reason: no licence, so no code. Suggested memories store facts about the person, which belongs in the backend under verified tenant identity (INV-05) with the owner's retention rules, not in the extension: this is an owner decision, not a gap. A live preview of partial results is a UI project of its own.

### 15. anomalyco/browse (MIT, ae5d9d07)
Read: README. An MCP server plus extension for other agents: background tab group, hand a tab back for a login or payment and continue on Continue, network capture, screen recording, a flight recorder, redaction. Xroga already has the tab group, the hand-back and continue, network diagnostics with masking, and Markdown export of a conversation with each step's first line. Not taken: screen recording (privacy and size), the MCP server (Xroga is the agent, not a tool for another agent).

### 16. uiuing/browser-agent (MIT, a8517e2c)
Integrated in an earlier session (failure chain, postcondition vocabulary, element state). Skill extraction from a verified run and row-by-row batch replay map to Xroga's `macro` and `batch foreach`, with the mend message added in batch 1.

### 17. jeet-dhandha/agent-webbridge (MIT, a14cd1dc): rejected
A Node daemon and extension that let an external MCP client drive several signed-in Chrome profiles in parallel. Xroga is the agent inside the browser and already runs parallel workers in their own windows; the daemon is a different product. Read: README only.

### 18. pinchtab/pinchtab (MIT, a6266202): benchmark ideas only
A Go HTTP server controlling Chrome for agents: token-efficient text, instances and profiles, a dashboard, an allowlist against indirect prompt injection. Read: README and its security section. Xroga's page text is already wrapped as untrusted data with the agent told never to follow it, its sites are limited by the person's blocked-sites list, and its measurements live in its own Chromium suite. Nothing taken; source not read.

### 19. motailab/open-browser-agent (Apache-2.0, b0791b8c)
Read: README and comparison table. Three-tier reading (markdown, numbered accessibility tree, JPEG), background tab group, focus and lifecycle emulation so background tabs are not throttled, per-domain allowlist, confirm before submit, a persistent JS REPL. All present in Xroga: text read then snapshot then screenshot, per-conversation tab groups, `Emulation.setFocusEmulationEnabled` and `Page.setWebLifecycleState` (scenario CAP-1), blocked sites and approvals, `run_script_console` and `python_repl`. Nothing to add. Source not read.

### 20. web-infra-dev/midscene (MIT, 4afc9fd1)
Read: README, the shared-agent API reference, the caching and skills documents, the `packages/core/src` layout. A vision-model test framework: natural-language act, query, assert and wait; plans and element locations cached by instruction with a fallback to the model when stale; a screenshot shrink factor; an HTML execution report; YAML scripts; per-app knowledge text.
Xroga's equivalents: plan reuse through `macro` and the learned route hints (`workflow-hints.ts`) with the mend message when a replay fails; `expect` postconditions and the done-judge for assertions; per-site context (`site-context.ts`); conversation export. Not taken: pixel-coordinate action from a vision model (Xroga's reads are exact from the page, with screenshots and marks only for canvases), YAML scripts and the test runner (a test framework, not an operator), cached query results (Midscene itself never caches them). Source of `core` not read beyond the layout.

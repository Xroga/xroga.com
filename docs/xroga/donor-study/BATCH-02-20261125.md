# Batch 2 (ledger rows 11 to 20): study, integration and tests, 2026-11-25

Method: each repository was cloned at its pinned commit (`C:/xr-donors`), its source read (not only its README), and every capability asked one question: does Xroga already do this, and does it work?
Where a repo's licence allows (MIT, Apache-2.0) its code was copied or ported with attribution (`apps/xroga-browser-extension/NOTICE`); where it could not be copied (OpenBUA has no licence) the system was rebuilt from the idea. Nothing was bypassed: a repo's own limits (a captcha solver, stealth) were not worked around.
Reading depth is stated per repo. The playwright source read is the current head (264e65c), not the ledger's pinned 2f1592a7.

## Per repository

### 11. ChromeDevTools/chrome-devtools-mcp (Apache-2.0, eb9b0302)
Read: README, tool reference (about 63 tools), design principles, the eight skills, `src/formatters`, `collectors`, `utils/WaitForHelper.ts`, `tools/lighthouse.ts` and its bundle.
Taken: Lighthouse (copied), cookie, storage, issue and weight diagnostics, three playbooks. Already in Xroga: input tools, navigation, emulation, console and network lists, endpoint map, `audit_page`.
Not taken, with reason: performance trace insights and heap snapshots (they need DevTools' trace engine, a large library for a developer task), logpoints, screencast, extension and PWA tools, WebAuthn, third-party developer tools, WebMCP (no site offers it yet), network mocking (it changes what a page receives and must be undone). The issue description texts are generated from DevTools at publish time and are not in the repo.

### 12. microsoft/playwright-mcp (Apache-2.0)
Read: README tool list (about 70 tools), the real tool code in `playwright/packages/playwright-core/src/tools/backend` (find, form, pdf, verify, response sections).
Taken: `read match` (its find), `save_page_pdf`, cookies and storage lists (read-only). Already in Xroga: click, drag, hover, type, fill_form, select, dialogs, upload, snapshot, console, network, tabs, offline and throttle, verification (`expect`).
Not taken: writing, deleting or restoring cookies and storage (they change logins: the person's approval and an exact scope are needed, and no agent task requires it), running Playwright code (`run_script_console` exists behind approval), video and tracing, locator generation, dropping files onto an element.

### 13. microsoft/playwright (Apache-2.0)
Test infrastructure and the home of playwright-mcp's tool code (read as above). Its actionability, auto-wait and ARIA snapshot behaviour are already the reference for `browser-control`. Nothing further.

### 14. AliSharjeell/OpenBUA (no licence found, 98d68ba4): rebuilt, not copied
Read: README, FORM-WORKFLOW, the agent module list (form agent, posting completion, application status guard, memory, page trust, parallel tasks). 
Rebuilt: memory with global and conversation tiers and suggestions that need a yes. Already in Xroga: challenge hand-over and blocked-sites queue, completion guards (`done` judge, postconditions), parallel workers, page trust (untrusted boundaries and now the injection scan).
Not built: a live preview tab streaming rows (a UI project: the answer table has Copy and Save as CSV), markdown table repair in the chat.

### 15. anomalyco/browse (MIT, ae5d9d07)
Read: README, `src/background` (agent relay, tab cleanup, popups, handoff notices, debugger hub).
Taken: tab tidy (idle close, mute), the hand-back and continue already existed. Not taken: the MCP relay (Xroga is the agent, not a server for another agent), screen recording, the Dia and other-browser workarounds.

### 16. uiuing/browser-agent (MIT, a8517e2c)
Integrated earlier (failure chain, postconditions, element state); skills extraction maps to `macro` and `batch foreach`, with the mend message from batch 1.

### 17. jeet-dhandha/agent-webbridge (MIT, a14cd1dc): different product
A Node daemon and extension for external MCP clients, several Chrome profiles, per-tab parallelism. Read: README, `src` file list, extension network tool. Xroga is the agent inside the browser and runs parallel workers in their own windows; nothing in it adds a capability to that.

### 18. pinchtab/pinchtab (MIT, a6266202)
Read: README, security, scrape documentation and code, `htmltrim`, `contentguard`, `idpi`, `remedy`, `cfchallenge`, `readiness`, package list; cloned `idpishield`.
Taken: HTTP-first site survey (`site_scan`), HTML trim (ported), prompt-injection scan (ported from idpishield). Already in Xroga: challenge detection (richer markers), error remedies (`failure-diagnosis`).
Not taken: stealth and the auto-solver (evasion and captcha solving), the daemon, dashboard, instances, scheduler and orchestrator (a control plane for other agents), HAR and heap tools.

### 19. motailab/open-browser-agent (Apache-2.0, b0791b8c)
Read: README, engine function list, dialog interceptor, the skill text. Xroga has the three-tier reading order, background tab groups, focus and lifecycle emulation (scenario CAP-1), blocked sites, approvals, `run_script_console` and `python_repl`. Not taken: the dialog interceptor that auto-accepts `confirm` (a "delete?" would be accepted without the person).

### 20. web-infra-dev/midscene (MIT, 4afc9fd1)
Read: README, API reference, caching, skills documents, `core/src` layout, the planning system prompt and action-readiness code.
Taken: the planning prompt's scope and completion rules (copied). Equivalents already in Xroga: plan reuse (`macro`, verified route hints), assertions (`expect`, the done judge), per-site context, export.
Not taken: pixel-coordinate action from a vision model (Xroga's reads are exact from the page), YAML scripts and the test runner, the HTML report (the conversation export covers sharing; a visual report would be a UI project).

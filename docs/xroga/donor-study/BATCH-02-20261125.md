# Batch 2 (ledger rows 11 to 20): study, integration and tests, 2026-11-25

Method: each repository was cloned at its pinned commit (`C:/xr-donors`), its source read (not only its README), and every capability asked one question: does Xroga already do this, and does it work?
Where a repo's licence allows (MIT, Apache-2.0) its code was copied or ported with attribution (`apps/xroga-browser-extension/NOTICE`); where it could not be copied (OpenBUA has no licence) the system was rebuilt from the idea. Nothing was bypassed: a repo's own limits (a captcha solver, stealth) were not worked around.
Reading depth is stated per repo. The playwright source read is the current head (264e65c), not the ledger's pinned 2f1592a7.

## Per repository

### 11. ChromeDevTools/chrome-devtools-mcp (Apache-2.0, eb9b0302)
Read: README, tool reference (about 63 tools), design principles, the eight skills, `src/formatters`, `collectors`, `utils/WaitForHelper.ts`, `tools/lighthouse.ts` and its bundle.
Taken: Lighthouse (copied), cookie, storage, issue and weight diagnostics, three playbooks. Already in Xroga: input tools, navigation, emulation, console and network lists, endpoint map, `audit_page`.
Not taken, with reason: performance trace insights and heap snapshots (they need DevTools' trace engine, a large library for a developer task), logpoints, screencast, extension and PWA tools, WebAuthn, third-party developer tools, WebMCP (no site offers it yet), network mocking (it changes what a page receives and must be undone). The issue description texts are generated from DevTools at publish time and are not in the repo.

### 12. microsoft/playwright-mcp (Apache-2.0)
Read: README tool list (about 70 tools), the real tool code in `playwright/packages/playwright-core/src/tools/backend` (find, form, pdf, verify, response sections).
Taken: `read match` (its find), `save_page_pdf`, cookies and storage lists (read-only). Already in Xroga: click, drag, hover, type, fill_form, select, dialogs, upload, snapshot, console, network, tabs, offline and throttle, verification (`expect`).
Not taken: writing, deleting or restoring cookies and storage (they change logins: the person's approval and an exact scope are needed, and no agent task requires it), running Playwright code (`run_script_console` exists behind approval), video and tracing, locator generation, dropping files onto an element.

## Checks (2026-11-25)

Unit tests: 1826 pass. Chromium suite on the final code: all 330 scenarios and the browser-data check pass, including the batch 2 scenarios `S3-lighthouse` (a real Lighthouse audit in 6.2 s), `S3-cookies-storage`, `S3-page-pdf`, `S3-browser-issues`, `S3-audit-lcp`, `S3-extract-cards` and `S3-read-styles`.
Live with the real model on staging, clean profile, real sites:
- whole-site audit of sqlite.org: 719 s, 38 turns, 88% of input from cache, `site_scan` used, 0 screenshots; the injection scan fired on documentation text (a false alarm, which led to the medium-or-higher threshold and web-text-only scope);
- Lighthouse on sqlite.org for a phone: 214 s, 17 turns, the `lighthouse` tool used, five ordered fixes returned;
- cookies, storage, browser issues, biggest requests and a memory request on sqlite.org: 126 s, 10 turns, 94% cached, 0 failed calls; `lighthouse`, `site_scan` and `memory` (remember, global) used;
- cookies and storage of python.org: 203 s, 18 turns, the automatic cookie read reached the model and the answer matched it.
Two things found by these runs and fixed: the model did not choose the new `diagnostics` kinds by itself (it read headers instead), so a task about cookies now has the cookie and storage reads run for it on each page it opens; and the test harness could not pair when the screen was off because the panel only refreshes while visible (now forced visible).

## Proven live since
- `save_page_pdf` through the Ask-mode "Save this file?" card: Chromium check `panel-save-pdf` (card shown, Save clicked, a real PDF of 62 KB in Downloads). The product build forces Auto mode, so its live runs reach the card only when the downloads permission is missing; granting it opens a Chrome dialog a script cannot click.
- Tab tidy over a real idle: check `tab-tidy-real-idle` (2026-11-25, no clock shortcut): an agent-opened tab was closed by the real alarm after 50 minutes (alarm every 10 minutes, idle limit 45); the tab in front and the person's tab stayed.

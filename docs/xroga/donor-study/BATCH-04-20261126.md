## Third pass (the same day): the three things the second pass listed as not built

| Gap | Built | Evidence |
|---|---|---|
| Crawlee request blocking | `emulate` takes `block`: any of images, media, fonts, styles, trackers. It sets `Network.setBlockedURLs` with address patterns (file endings, and tracker hosts), is lifted by `block: []`, and `reset` lifts it. A reload is needed to see the effect. Addresses without a file ending (a one-pixel counter) are not caught, and the tool says so. | 14 unit tests in `emulate.test.ts`; real Chromium on https://en.wikipedia.org/wiki/Domestic_cat: 13 pictures loaded, 1 with images blocked, 13 again after the block was lifted |
| Audio and video transcription | New tool `transcribe` (`src/agent/transcript-format.ts`, `src/extension/transcribe.ts`, a handler in the offscreen document). The file is fetched (200 MB limit), decoded by the browser to 16 kHz mono, and Whisper tiny (English, or multilingual when a language other than English is named) runs through transformers.js 3.8.1 with a single-thread WebAssembly runtime vendored in `public/speech`. The model (about 41 MB, quantised) is downloaded once from Hugging Face and kept in the browser cache. Output is lines with times; `find` narrows it; `seconds` (default 300, at most 1800) sets how much is read. Only the sound of a video is read. | 6 unit tests; real Chromium on the Open Speech Repository recording OSR_us_000_0010_8k.wav (33 s): all ten Harvard sentences came back with correct times, 43 s in all including the model download |
| Docling layout and table models | `read_pdf` takes `layout: true`. Docling's Heron layout model (Apache-2.0 ONNX export, 171 MB, downloaded once and cached) finds the regions of each drawn page; for every table region, Microsoft's Table Transformer (MIT, 30 MB, downloaded once) finds the rows, columns, header rows and spanning cells, and `src/agent/layout-assemble.ts` puts the words (from the PDF text layer, or from text recognition on a scan) into Markdown in reading order: title and headings, paragraphs, lists, captions, footnotes, formulas, code, pictures (with any text inside them), tables as grids, with page headers and footers left out and full-width regions splitting two-column bands. There is no page cap (the caller picks the pages), and a page stored rotated is read as it looks, because words are placed through the viewport's own transform. The result says per table what the table model found, and falls back to the gaps between words when it finds no grid. | 8 unit tests on the assembly (rotation maths included); real Chromium: https://arxiv.org/pdf/1512.03385 gives the title, Abstract and Introduction as headings, pictures with their text, figure captions, Table 2 as a clean grid and Table 1 with one row per stage and separate cells for stage, size and blocks; https://www.federalreserve.gov/monetarypolicy/files/fomcprojtabl20240320.pdf page 2 (stored rotated 90 degrees) gives a 13-column projections table with every number in its column; ten pages in one call took 177 s warm |

What is still imperfect, said plainly:

- The table model is Table Transformer, not TableFormer. TableFormer's only ONNX export is a third-party two-stage pipeline with no browser-ready build. Its grids are good, not perfect: on Table 1 of the ResNet paper the `conv1` label lands in the header row, and on the FOMC table two stacked rows (a variable and its December projection) are joined into one cell block. Every number stays in its right column.
- Layout reading is slow on a computer without a graphics path for the model (single-thread WebAssembly): about 17 s a page once the models are loaded (the first call also downloads about 200 MB), and the whole call waits for the pages asked for, so ask for few pages at a time.
- Text set sideways inside an upright page (a vertical axis label) is skipped, as before.
- Transcription is the tiny model: names and numbers can be wrong, and the tool says so in its output. Music and non-speech sound come back as nothing.
- The extension package grew by about 5.3 MB compressed (11 MB of the plain WebAssembly ONNX runtime and 0.9 MB of transformers.js, unpacked): the three models are downloaded on use, not shipped.

## What else was added from reading

- `read_file` and the article reader are announced to the model when a tab shows such a file, as the PDF reader already is.
- Bundled skill `reading-documents-articles-and-feeds` tells the model which reader to pick (article, data, read_file, read_pdf, untilEnd, holdMs) and what to quote back.
- The skill ranker test now checks every bundled skill is first for at least one request, against the catalog size instead of a fixed 19.

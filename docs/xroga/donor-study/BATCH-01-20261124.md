# Donor study, batch 1 (ledger rows 1 to 10), 2026-11-24

Method: each repository was cloned at the commit the ledger pins (blobs fetched on checkout) and read; for each one this records what it is, what it does that matters
for a universal browser operator, whether Xroga already had it, what was taken, and what was left and why. "Read" says how deep the reading went. Licences are kept;
nothing was copied verbatim except where a file says so; patterns were written fresh for this code base.

Depth is stated plainly: README and design documents were read for every repository, and source was read where a capability was taken. A second pass on the
repositories marked "second pass" is still owed before the batch is called finished.

## What changed in Xroga from this batch (all unit-tested; Chromium-tested where noted)

| Capability | From | Xroga change |
|---|---|---|
| Structured extraction of tables, ARIA grids, result lists and repeated cards into rows with column names, links, merged-cell count, stated total and "more below" evidence | Tencent/BrowserSkill (`tool.extract`, structured-extraction.md), browserbase/stagehand (`extract`) | New layer tool `extract_rows` (`core/tools/extract-rows.ts`, probe `extractRows`), scenario `S3-extract-rows` and fixture `c-extract-rows.html` |
| The extracted rows are the working set of list work: remove duplicates, filter, sort, group without the model retyping a cell | browser-use (the model works on data it holds, not on cells it re-reads) | `data_ops` takes its rows from the last `extract_rows` or from its own last result (`agent/loop.ts`, `agent/data-ops.ts`) |

## Row by row

### 1. nanobrowser/nanobrowser (Apache-2.0, 291d5f39)
Read: README, tree. The foundation Xroga's extension was forked from (planner and navigator loop, side panel, MV3 shell). Xroga replaced the loop, the tool layer and the
state model long ago. Not taken: nothing new. Second pass: diff the upstream fixes made since the fork point against Xroga's copy (the ledger still lists this as not done).

### 2. vercel-labs/agent-browser (Apache-2.0, 4605d82c)
Read: README, the 17 KB core skill, the list of its skills. A native CLI with a snapshot-and-ref loop (`snapshot -i`, `@eN` refs), `snapshot --delta`, `screenshot --if-changed`,
`read <url>` over HTTP preferring markdown with `--outline` and `--filter`, waits on text, URL or a page condition (it warns against `networkidle` as a generic wait), WebMCP tool
discovery, saved flows that replay over HTTP first, `derive-client` (record a HAR, generate an API client), an auth vault, domain allowlists and a dogfood QA skill.
Xroga already had refs, diffs, text and URL waits and a server-side `http_get`. Taken: `screenshot ifChanged`. Not taken yet: markdown reading of a URL with outline and filter (Xroga's
`http_get` is a server route that returns text; an outline and filter mode is a small addition), WebMCP discovery (an experimental page API), HAR-to-client (a larger project, listed
for a later batch). Second pass: the dogfood skill (exploratory QA method) and the derive-client skill.

### 3. dylansantwani/openbrowser (MIT, 1f670809)
Read: README (tools, token-cost and difficult-sites sections). Fifteen tools grouped by `action` enums, trusted input through the debugger, compact accessibility trees, `mode diff`,
`expect` on actions, `browser_batch` with `when`/`unless`/`repeat`, and `browser_macro`. The difficult-sites table lists what breaks automation (synthetic clicks, iframes,
cross-origin coordinates, covered elements, shadow DOM, framework-controlled inputs, hidden file inputs, drag libraries, re-rendered refs, off-screen elements, popups, hidden tabs, dialogs).
Xroga already covers each of those rows (the earlier sessions' scenarios exercise them) and already adapted batch control flow. Taken: `macro`. Second pass: read `docs/TOOLS.md` for any
parameter Xroga lacks.

### 4. Tencent/BrowserSkill (MIT, ae87b539)
Read: README, `docs/structured-extraction.md` and the docs list. Shared control with pause and reconcile, a visible Agent Window, operation audit, task video, wait-for-element, long screenshot,
scroll-to, the step and view observation store, evidence behind a failure (requests, response bodies, console, page changes) and structured extraction with provenance, spans and coverage.
Xroga already had shared control (the human-control guard), evidence in action receipts and diagnostics. Taken: structured extraction (`extract_rows`: rows, columns, links, merged cells,
stated total, more-below). Not taken yet: field-selector extraction of arbitrary cards by CSS (Xroga detects repeated cards by structure instead, with no selector from the model), hidden
frame handles, CSV export. Second pass: long-screenshot and scroll-to docs.

### 5. browser-use/browser-harness (MIT, 22ecf854)
Read: README and the interaction-skills list. The helper layer under browser-use: CDP helpers, an agent workspace where the agent writes reusable helpers, and 17 short interaction skills
(dialogs, downloads, drag-and-drop, dropdowns, iframes, cross-origin iframes, scrolling, shadow DOM, tabs, uploads, viewport, screenshots, network requests, cookies, profile sync, print as PDF,
make-video). Most are one or two lines; the scrolling note (a hidden tab can leave a wheel command unanswered; use focus emulation, never fake the scroll) is already how Xroga scrolls.
The README's matched benchmark (100 tasks, one agent) shows no tool wins on score and that fewer input tokens per task was the harness's edge (2.1M against 3.3M to 6.7M median).
Nothing to take that Xroga lacks. Second pass: the 3 longer skills (connection, tabs, make-video) for details.

### 6. alibaba/page-agent (MIT, d8dd3344)
Read: README. An agent that lives inside the page (one script, text-based DOM manipulation, no screenshots), with an optional extension for multi-page tasks and an MCP server. The ledger already records
a behaviour comparison: Xroga finds and activates the controls it targets. Not taken: the in-page deployment model (Xroga drives from the extension). Second pass: its prompt and DOM-to-text
module, to compare how it names controls with Xroga's outline.

### 7. derpx06/webgenie (Apache-2.0, 56b5d8bc)
Read: README. A planner and a navigator with replanning on stalls, verification by comparing the page before and after every page-changing action, route memory (the pages and kinds of
elements used, keyed by the start page, never typed text), steering a running task by typing, checkpoints every step, a domain firewall, a separate personal-data check before sending
an address to a site, passwords never shown to the model, and opt-in browser data tools (tabs and tab groups, history, bookmarks, reading list, downloads, sessions).
Xroga already has before/after verification, plans and replanning on stalls, checkpoints and resume, route hints and a domain policy. Not taken yet: the browser data tools
(history and bookmarks need optional permissions requested with a person's click: planned as `browser_data`), and a separate personal-data check. Second pass: the tool code for tab groups.

### 8. openbrowse-ai/openbrowse (MIT, 9c1bec9d)
Read: README, architecture outline. Side panel agent with a per-conversation workspace in the browser's file system, JavaScript and Python execution, skills following the agentskills.io
standard, MCP connectors, Spaces and AI Tidy for tab organisation, a command palette, 130 model providers. Xroga already follows the agentskills standard for skills and has a save-file workspace and
connected apps. Not taken: a Python runtime in the extension (not allowed under MV3 content rules without a bundled interpreter), tab organisation (belongs with `browser_data`). Second pass: the skills loader and workspace tools.

### 9. browserbase/stagehand (MIT, 4d72a87f)
Read: README. `act`, `extract` (schema-validated) and `observe`, self-healing and cached actions, credentials never sent to the model because `observe` returns selectors. Test reference only (its
benchmark needs a paid cloud). Taken: the extraction idea (`extract_rows`); schema validation of extracted values is done by the agent when it answers. Not taken: cached action replay beyond `macro`.
Second pass: the extract implementation and its evaluation tasks, as holdout ideas for Xroga's own evals.

### 10. browser-use/browser-use (MIT, ccbdb809)
Read: README, `agent/prompt.py`, module layout. The agent is a model, a persistent Python REPL and CDP: one cell can do many actions, loops and variables, partial results are checkpointed, and a result
is delivered from the variable that holds it. Its prompt insists on evidence: keep observations unchanged, say what was discovered, attempted, fetched and verified, derive logs from real requests,
never invent a status; a failed call may have partly run, so inspect before retrying. It also offers a web `search()` helper (search pages in a browser are slow and trigger anti-bot checks), secrets typed by
name so the model never sees the value, and a captcha solver.
Xroga's answer to code-as-action is `batch` (loops, conditions, foreach) plus `macro` and `data_ops`; extension pages cannot run model-written code (MV3 CSP), so a REPL is not possible here. Taken: the
working-set idea (`extract_rows` into `data_ops`), the uncertain-write discipline (already in Xroga: resume pauses on a write that may have been delivered). Not taken: a captcha solver (Xroga does not bypass CAPTCHAs),
secrets by name (needs a credential store; not built). Gap found, not yet built: a `web_search` tool. Xroga has the server's search client (Parallel) behind tenant-scoped, metered gateways but no route for the
browser operator, so client research drives search result pages. Adding the route touches reviewed server code and is the next item for this batch. Second pass: `agent/loop.py` and `judge.py`.

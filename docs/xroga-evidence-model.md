# Xroga UI/UX Step 1 Evidence, Approval, and Receipt Model

Evidence is only created from real backend, artifact, provider, or project state. The canonical evidence contract supports web, file, database, calculation, tool, command, check, browser, test, deployment, Git, action, artifact, and integration evidence.

Evidence can link to events, blocks, and artifacts. The UI uses progressive disclosure so a normal result stays concise while a developer can inspect available command IDs, check IDs, runtime IDs, durations, exit codes, paths, and redacted logs.

Approval and connection blocks are presentation contracts only. Backend authorization remains authoritative. A project being open does not grant write, publication, deployment, financial, destructive, or third-party communication permission.

Receipts describe actions that actually reached an external system. They retain service, target, status, timestamp, external reference, URL, reversibility, approval identity, and evidence references when supplied. No renderer synthesizes a receipt from intent alone.

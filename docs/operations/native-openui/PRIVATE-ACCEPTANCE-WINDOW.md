The version 3 manifest binds the frontend and API to the same PR source and an immutable API image digest. It uses the existing archive builder, Artifact Registry, managed staging Supabase project `dqxnatoessviphudbhei`, and canonical ledger. An old manifest, production issuer, unreviewed API address or browser automation API identity fails admission.

### Preflight and closeout

1. Require all exact-source CI, original archive generation and successful image digests. Verify release readbacks for both services, account IAM, no unauthenticated invoke, the isolated issuer and storage/ledger realm, and a regular staging account. Start with provider access absent. Prove foreign-account reads and direct unauthenticated access are denied. No production test users.
2. Start the paid phase only after validating the current ledger, approved model, limits and no pending receipts. Enable native generation only on the dedicated API. Use the normal Workspace composer. End the phase at the first failed security, provenance or accounting check.
3. Run four distinct prompts: concise prose with no widgets; a multi-tenant SaaS diagram with tenant authorization, database roles and a signed billing webhook workflow; a $25 workshop calculator at 40 attendees with a 20/40/60 chart, table and reset; a scoped primary-source comparison with inline citations. For the last prompt approve one Search confirmation only. Check the expected math, displayed sources and actual links, diagram edges, usable keyboard controls, Copy, private Share, Reopen and mobile fit. Capture 390 and 1440 CSS px in light and dark. Record provider IDs and actual amounts without credentials. Reuse settled results for persistence and theme checks.
4. Disable the dedicated paid cycle and revoke the two services' temporary grants. Delete only the dedicated test services, their temporary identities and task-owned archive objects within the agreed retention window. Recheck the shared API and production readbacks without changing them. Keep sanitized screenshots and ledger receipts. A failure after provider admission requires reconciliation before any new call.

The production candidate still needs authenticated acceptance and a separate promotion decision. Its rollback restores the previous compatible frontend and decoder while leaving saved native documents readable.

# Native OpenUI answer evaluation

The worktree starts at verified main 6652ea3765540b2f78a7cf8bc4ac70e3d184b643. PR #950 and the current Workspace renderer are separate and unchanged. This package is the standalone evaluation step in the requested sequence. It does not switch Workspace traffic or remove compatibility code.

## What this source implements

- DeepSeek receives a prompt generated by the same OpenUI registry used in React. It supplies readable prose and an optional native Lang program in one request. There is no V2-to-OpenUI translation or formatting-model request.
- A bounded preflight rejects undeclared references, cyclic or over-expanded programs, external tool operations, arbitrary source IDs and unsupported components before invoking the pinned OpenUI parser. The browser revalidates. The model can change local widget state but cannot dispatch an external action.
- The app uses the existing model quota, reservation, egress and settlement path. The evaluator is off without an exact owner ID and a positive per-request cap. It requires a verified founder identity, confirmed email, current owner role, AAL2 and an issued server tenant context. The backend rechecks the owner before dispatch. Supabase access uses the existing caller-scoped client; no table grant, schema, signing key or role changes.
- We use Open Intelligent UI source for presentation and deterministic functions and adapt CopilotKit's accessible Tabs under MIT. See coverage.json for the complete evaluated CopilotKit standard catalog. Native streaming rendering was exercised using an incomplete program with a complete prefix. The live endpoint withholds output until the existing provider accounting path verifies and settles usage.
- The runtime does not fetch content based on a model-authored URL. Trusted evidence IDs can resolve to source links. This evaluator has no evidence-retrieval flow, file upload, network-backed maps or authorized media source. Those cases are not counted as passes.

## Verification

From a frozen install using the repo's Node and npm versions:

    node scripts/generate-native-openui-spec.mjs --check
    node node_modules/tsx/dist/cli.mjs --test backend/src/ai/nativeOpenUi.test.ts
    node scripts/verify-native-openui-browser.mjs <evidence-directory>

The Chrome fixture harness serves the actual presentation components over loopback. It checks nine scenarios against six theme and viewport combinations, keyboard calculator and reset, numeric sort, chart data accessibility, highlighted code, tabs, safe evidence links, fallback and a stream prefix. It blocks and records attempted off-origin requests. Its asset counts are from a minified esbuild fixture with inlined fonts, not Next.js transfer measurements.

No live Zurelay request, paid staging build, production modification, authenticated Workspace check or deployment was performed for this branch. The prompt suite records all live cases as NOT_RUN. Main's sidebar assertions and source-bound security evidence drift must be resolved and reverified before a release.

3. Run one fresh DeepSeek request per approved test prompt, no retries. Start with short, comparison, workshop calculator and architecture. Reconcile each against the canonical ledger and provider receipt. Record prompt ID, actual model, token counts, elapsed time, finish status and settled charge. Independently score correctness, completeness, evidence fidelity, visual usefulness, accessibility, interactivity, viewport, latency and cost. Do not extrapolate the fixture timings to provider or Workspace performance.
5. Only after independent acceptance, add the native answer format to existing chat persistence and select it for new Workspace responses under an opt-in flag. Keep old payloads readable. Test live stream/accounting behavior, abort/failure, unauthorized access, files and citations, Copy/Share/Reopen, and compare the actual Workspace render. Keep the previous verified frontend/backend available for immediate rollback until historical compatibility and canary acceptance pass.

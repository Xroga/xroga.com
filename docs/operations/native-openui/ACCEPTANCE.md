# Native OpenUI answer evaluation

The worktree starts at verified main 6652ea3765540b2f78a7cf8bc4ac70e3d184b643. PR #950 and the current Workspace renderer are separate and unchanged. This package includes the standalone gate and a disabled Workspace integration for authenticated staging. The Workspace switch is separate from the four-call evaluator.

## What this source implements

- DeepSeek receives a prompt generated by the same OpenUI registry used in React. It supplies readable prose and an optional native Lang program in one request. There is no V2-to-OpenUI translation or formatting-model request.
- A bounded preflight rejects undeclared references, cyclic or over-expanded programs, external tool operations, arbitrary source IDs and unsupported components before invoking the pinned OpenUI parser. The browser revalidates. The model can change local widget state but cannot dispatch an external action.
- The app uses the existing model quota, reservation, egress and settlement path. The evaluator is off outside staging or without an exact owner ID and an expiring run that binds each prompt to one reservation UUID and a total cap. It requires a verified founder identity, confirmed email, current owner role, AAL2 and an issued server tenant context. The backend rechecks the owner before dispatch. Supabase access uses the existing caller-scoped client; no table grant, schema, signing key or role changes.
- We use Open Intelligent UI source for presentation and deterministic functions and adapt CopilotKit's accessible Tabs, searchable ChoicePicker and local review interaction under MIT. See coverage.json for the complete evaluated CopilotKit standard catalog. Native streaming rendering was exercised using an incomplete program with a complete prefix. The proposed live evaluator sends progress over SSE and releases the answer only after the existing provider accounting path verifies and settles usage. This does not verify progressive provider text in Workspace.
- The runtime does not fetch content based on a model-authored URL. Trusted evidence IDs can resolve to source links. This evaluator has no evidence-retrieval flow, file upload, network-backed maps or authorized media source. Those cases are not counted as passes.

## Verification

From a frozen install using the repo's Node and npm versions:

    node scripts/generate-native-openui-spec.mjs --check
    node node_modules/tsx/dist/cli.mjs --test backend/src/ai/nativeOpenUi.test.ts
    node scripts/verify-native-openui-browser.mjs <evidence-directory>

The Chrome fixture harness serves the actual presentation components over loopback. It checks eleven scenarios across 1440, 1280, 768, 390 and 320 CSS pixels in light and dark, keyboard calculator and reset, linked product marks, numeric sort, accessible chart data, connected diagram rendering and zoom, highlighted code, tabs, searchable review and reactive data, safe evidence links, fallback and a stream prefix. It blocks and records attempted off-origin requests. Its asset counts are from a minified esbuild fixture with inlined fonts, not Next.js transfer measurements.

No live Zurelay request, paid staging build, production modification, authenticated Workspace check or deployment was performed for this branch. The parity benchmark preserves the 20 exact prompts. Two fresh ChatGPT baselines were captured and the corresponding Xroga fixture screenshots are separate evidence. There is no live head-to-head score yet. Stale caller review and squash ancestry references were reconciled with Git history. The audit's source integrity check does not establish staged tenant security.

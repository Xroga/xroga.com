# Teams collaboration references

- [Life Hub workspace selection](https://github.com/Trias1/life-hub/blob/9565adba042ab872198c1fcda389dc408b80afff/src/lib/workspace/server.ts) ([MIT license](https://github.com/Trias1/life-hub/blob/9565adba042ab872198c1fcda389dc408b80afff/LICENSE)): a selected workspace is only a preference; each operation derives scope from verified membership. The Teams drawer uses the same boundary: an active membership selects a roster, and the browser discards responses that don't match the selected team and current revision. No upstream code is vendored, and selecting a team in the drawer does not grant access to shared resources.
- [Yjs](https://github.com/yjs/yjs): a candidate for merging simultaneous text edits. It does not handle Xroga authorization, access revocation, durable revisions, or individual AI usage and is not installed.

Before enabling shared Workspace resources, each conversation, project and file needs an explicit server-verified owner scope. A shared resource still uses the requesting user's execution identity, plan, and private integration connection. Retain personal ownership unchanged; prove member access, nonmember denial, immediate revocation and no cross-user credit use in the isolated rollout.

# XROGA AI content and topical-authority strategy

The strategy favors a small number of useful, evidence-backed pages. No search volume, keyword difficulty, CPC, or traffic estimate is supplied; each requires an external keyword dataset.

## SERP and intent observations

Permitted web search on 2026-08-11 showed that current results for AI coding/app-builder queries emphasize: autonomous repository work; owned/exportable code; GitHub and deploy-anywhere workflows; app creation; and verification/governance. Examples include [Cursor](https://cursor.com/), [Dyad](https://www.dyad.sh/), [Codebolt](https://codebolt.ai/), and [OpenThorn](https://www.openthorn.app/). These are intent observations, not endorsements or claims of ranking position.

XROGA's clearest defensible angle is the connected, evidence-backed loop: inspect the repository, implement, validate, repair, and publish through authorized accounts. Content should demonstrate that loop rather than repeat generic “best AI” claims.

## Editorial sequence

1. Keep product, pricing, docs, and company facts consistent.
2. Expand existing docs for repository safety, validation evidence, GitHub delivery, Vercel verification, and failure recovery.
3. Publish one reproducible “AI-generated code verification” methodology with fixtures and raw results.
4. Turn recurring real support questions into docs only after they recur and can be answered factually.
5. Add comparison content only when it is dated, sourced, fair, and maintained; do not publish “alternatives” pages that merely repeat competitor names.

## Programmatic SEO decision

Do not implement programmatic SEO. The repository has no genuine dataset that would make hundreds of distinct pages independently useful. Revisit only if XROGA publishes maintained benchmark results or a verified integration catalog with unique setup guidance per provider.
